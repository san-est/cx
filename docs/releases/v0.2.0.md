Kubernetes joins AWS and gcloud: contexts switch per shell and have their own
dashboard pane. Key-based AWS profiles can be created from the command line.
The code that edits `~/.aws/credentials` and `~/.aws/config` is now fuzzed,
which turned up four bugs, one of them in deleting profiles.

## Added

**Per-shell Kubernetes contexts.** `kubectl config use-context` changes every
terminal at once, because it writes `~/.kube/config`. cx now pins the context
to one shell instead:

```sh
cx use k8s prod       # this shell only
cx clear k8s          # back to the shared default, still pinned
```

cx does this with a four-line overlay at the front of `KUBECONFIG` that carries
only `current-context`. Nothing is copied, so nothing goes stale and no tokens
or certificates are duplicated, and `~/.kube/config` is never written. With the
overlay in place, `kubectl config use-context` itself becomes shell-local.
`cx status` gains a K8S section, contexts naming a missing cluster or user are
flagged, and production marking extends to them (`k8s = prod, *-prod`).

**A Kubernetes pane in the dashboard.** `enter` pins the selected context to
this shell. The pane is hidden when kubectl can't be read. Each pane now names
its own scope column (REGION, PROJECT, NAMESPACE) instead of calling them all
SCOPE.

**`cx add aws <name>`** creates a key-based profile without opening the
dashboard:

```sh
cx add aws client-prod --region eu-west-1
```

The secret access key and session token are read from the terminal without
echo, or from stdin, and never from a flag: arguments are visible to every
process on the machine and stay in shell history. Replacing an existing
profile needs `--force`.

## Fixed

**Deleting a profile that wasn't last in its file didn't delete it.** cx removed
only the blank line after the section and reported success, leaving the
credentials in place. This affected every profile except the last one in
`~/.aws/credentials` and `~/.aws/config`.

**A key could be written into the wrong profile.** The writer recognised a
section header only when the line ended in `]`, but the parser (like the AWS
CLI) also accepts `[b] ; note`. Writing to the profile above such a header
appended the key to the one below it.

**CRLF files were rewritten as LF.** A credentials file last edited on Windows
had every line changed by any write, not only the section being written. Line
endings are now kept as they are.

**Duplicate sections or keys were edited where nothing reads them.** When a
profile or key appears twice, the later one wins, but cx edited the first.
Writes now go where they will be read, and deletes remove every copy of the
section.

**A value with a line break could add lines of its own** to a credentials or
config file, such as a whole extra profile. Such values are now refused.

**The production flag was missing from unselected rows** in every dashboard
pane, since production marking shipped in v0.1.2.

## Security

`golang.org/x/sys` and `golang.org/x/text` are updated past
[GO-2026-5024](https://osv.dev/GO-2026-5024) and
[GO-2026-5970](https://osv.dev/GO-2026-5970). `govulncheck` showed cx never
called the affected code. CI now runs a pinned `govulncheck`.
