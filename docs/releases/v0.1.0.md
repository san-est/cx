First release.

`cx` shows the cloud account your shell is actually pointed at — AWS profiles,
gcloud configurations, and Application Default Credentials — on one screen, and
switches between them per shell.

It exists because `gcloud config configurations activate` writes to a
machine-wide file, so switching in one terminal silently retargets every other
one, and because ADC is a separate credential store from the active gcloud
configuration. Between those two facts, `gcloud config list` can say `staging`
while `terraform apply` goes to production, with nothing on screen to warn you.

## What works

- **Dashboard** across AWS profiles, gcloud configurations and ADC, with
  credential kind and live status probed concurrently against STS and gcloud
- **Cross-target hazard detection** — the warnings no single row can express: a
  gcloud target inherited from the machine-wide file, an `active_config` naming
  a configuration that no longer exists, ADC's quota project disagreeing with
  the active gcloud project, ADC authenticating as a different principal, and
  `CLOUDSDK_*` variables silently overriding the active configuration
- **Per-shell switching** that only ever sets environment variables, so a switch
  in one terminal cannot retarget another
- **Add, edit, delete and re-authenticate** targets from the dashboard, writing
  `~/.aws/config`, `~/.aws/credentials` (mode 600) and `~/.config/gcloud`
- **`cx status`**, which exits `2` when it finds state that can misdirect a
  command, so it can gate a script
- **A prompt segment** that reads only local files — about 5 ms, against roughly
  800 ms for a single `gcloud config get-value` — with a starship recipe that
  stays invisible unless something is wrong

## Requirements

The shell wrapper is required for switching, and adds the prompt segment:

```sh
echo 'eval "$(cx shell-init zsh)"' >> ~/.zshrc     # or:
echo 'eval "$(cx shell-init bash)"' >> ~/.bashrc
```

A program cannot change its parent shell's environment, so `cx` writes changes
to a scratch file that the wrapper sources. Without it installed, `cx` says so
rather than appearing to work.

zsh and bash are both supported. On zsh the prompt segment is wired into
`RPROMPT` automatically; on bash, add `$(cx_prompt)` to your `PS1` — see the
README. fish and nushell are not supported.

## Not in this release

- The Kubernetes pane, with a per-shell kubeconfig copy so `use-context` in one
  terminal cannot retarget another
- Marking targets as production and requiring confirmation to switch to them
- `cx add aws <name>` for creating static-key profiles from the command line

## A note on versioning

This is `v0.1.0` and pre-1.0 on purpose: the command surface, flags and
environment variable names may still change. Pin the version if you script
against it.
