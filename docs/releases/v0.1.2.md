Production targets can now be marked, and switching to one asks first. GCP
auth failures also say what is actually wrong.

## Added

**Mark targets as production.** List them by name in `~/.config/cx/config`
(`$XDG_CONFIG_HOME` is honoured, `CX_CONFIG` overrides):

```ini
[production]
aws = client-prod, *-prod
gcp = acme-prod, prod-*
```

Flagged targets show `[prod]` in the dashboard, the context header,
`cx status` and the prompt segment. `cx use` and the dashboard's `enter` both
ask before switching to one; with no terminal, `cx use` refuses unless given
`--yes`. A malformed pattern is reported rather than silently protecting
nothing.

`cx status`'s exit code is unchanged: deploying to production is legitimate,
and exit `2` stays reserved for a shell that can be misdirected.

## Fixed

**GCP auth failures showed gcloud's boilerplate instead of the error.** A
configuration whose token needed re-authentication was reported as:

```
to select an already authenticated account to use.
```

gcloud ends every auth error with the same "if you have already logged in with
a different account" hint. The error matching was case-sensitive and missed
gcloud's `Reauthentication failed`, so cx fell back to the last line of output,
which is always that hint. It now reports
`refresh token rejected - run: gcloud auth login`, recognises the
"no active account selected" case, and falls back to gcloud's first line, the
one that names the problem.
