A correctness fix for the `cx status` exit code, and the release now carries
its own provenance.

## Fixed

**`cx status` under-reported a forgotten `CLOUDSDK_CORE_PROJECT`.** The alert
existed but could never reach `DANGER`, so the command exited `0` and any
script gated on it carried on:

```sh
cx status --no-probe >/dev/null || { echo "refusing to apply"; exit 1; }
```

The audit compared the override against the active configuration's project, but
by then the loader had already replaced that project *with* the override — so
the comparison asked whether the override differed from itself, which it never
does.

This is the one piece of gcloud state that reaches Terraform: the google
provider reads `CLOUDSDK_CORE_PROJECT` when no project is set in the provider
block, and ignores gcloud's configuration files entirely. A forgotten export
really can retarget an apply, and in v0.1.0 the gate let it through.

If you use `cx status` to gate anything, this is worth taking.

## Changed

Releases now attach their build provenance as `cx_<version>.intoto.jsonl`. The
attestation was already there — `gh attestation verify` has always worked — but
it lived only in GitHub's API. Shipping the bundle means the release carries its
own proof, verifiable without contacting that API.

## Also in this release

Documentation caught up with the code: **bash has always been supported** by
`shell-init`, and nothing outside an error message said so. The prompt segment
is wired into `RPROMPT` automatically on zsh; on bash, add `$(cx_prompt)` to
your `PS1` — the README has the line.

The Go floor dropped from 1.27.1 to **1.25**, which is what the code actually
needs, so `go install` works on considerably more machines.

`cx version` now reports the release, commit, dirty state and platform.
